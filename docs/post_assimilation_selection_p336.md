# P336: conditional post-assimilation candidate selection

P335 establishes shared ordinary/conditional handoff closure for the opt-in
FP64-internal/FP32-stored recipe. P336 searches the two existing body-control
modes while keeping the current head's complete merit and the original
nonlinear/raw constraints. This is an experiment, not a new default or a
quality claim. Physical F health does not certify Gaussian footprint quality.

The live selection owns the actual accepted velocity sequence and uses only
its current owner, references, lambda, history and expiring full-merit evaluator.
The supplied successor is an owned policy estimate from a prior actual identity
run. Materials/grid/horizon must match; releasing current pins is unsupported.
Future motion is measured over estimated surviving-free IDs. Newly imposed pins
are reported separately: their zero velocity cannot count as natural rest.

Search retains three original repeats, at most eleven candidate forwards and
three confirmations with unchanged thresholds. The search returns an owned,
detached snapshot of its last successful `confirm_2` before archival callbacks
can mutate buffers. Registration waits for final generation/merit checks and
does not perform another forward. It checks full-state health and current merit
again. Only the raw head enters the ordinary runner; estimated Fp/pins are never
installed. No admitted candidate returns the exact original result.

After a selected head's ordinary commit, its real prepared successor and passive
coast must be measured, followed by ordinary controlled continuation. A later
failure rejects that experimental branch; it cannot restore an earlier runner
transaction. Differences from frozen policy must be recorded. Actual policy,
full-morph/gallery, natural-rest and4K appearance gates remain necessary.

Independent CPU gates:36 search-core cases;68 registration/selection/pipeline
cases. An additional actual N27/T20/dt.002/dx.5/grid16^3 CPU MPM/search test passes
with synthetic constant data constraints and a raw-quality stub. It exercises
real optimization, three confirmations and raw-head registration with newly
pinned particles. This last test is state-delivery evidence only, not shape or
rendering-quality evidence. Its explicit hyde06 CUDA version prohibits numerical
array downloads; actual CUDA execution is pending.

No changes to default loss, rendering covariance, production recipe or deliverable
are authorized by a small capability pass. Report donor optimizer rendering
norms and lambda separately from selected-forward observations; those norms are
not a causal movement fraction or exact exported4K covariance supervision.
